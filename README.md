# 💘 소개팅 매칭

프로필을 작성하면 서로 조건이 맞지 않는 사람을 걸러내고, 공통점을 점수로 매겨 순위를 정한 뒤 1:1로 매칭해 주는 프로젝트입니다. 매칭될 때마다 **왜 매칭됐는지** 이유도 알려 줍니다.

외부 패키지 없이 Node.js(18 이상)만 있으면 실행됩니다.

## 🌐 데모 (설치 없이 바로 체험)

👉 **https://jeonghossi.github.io/blind-date-matching/**

서버 없이 HTML만으로 동작하는 깃허브 페이지 버전입니다.
- 데이터는 **각자 브라우저에만** 저장돼요 (다른 사람과 데이터가 공유되지 않아요)
- 새 탭에 주소를 붙여넣고 다른 테스트 계정으로 로그인하면, 한 브라우저 안에서 두 사람처럼 랜덤 매칭을 테스트할 수 있어요
- 혼자라면 🎲 랜덤 → ⏳ 대기 중 → 🤖 봇이랑 테스트

| | 서버 버전 (`npm start`) | 깃허브 페이지 버전 (`docs/`) |
|---|---|---|
| 데이터 저장 | 서버 (`data/`) — 모든 사용자 공유 | 브라우저 localStorage — 각자 따로 |
| 실시간 연결 | Server-Sent Events | 같은 브라우저의 탭끼리 (storage 이벤트) |
| 로그인 | HttpOnly 쿠키 | 탭마다 따로 (sessionStorage) |

깃허브 페이지 버전은 `src/`·`public/`의 코드를 그대로 쓰고, 서버 역할만 [pages/local-backend.js](pages/local-backend.js)가 대신합니다. 코드를 고친 뒤에는 다시 만들어 주세요.

```bash
npm run build:pages   # docs/ 다시 생성
```

## 실행

```bash
npm start      # http://localhost:3000
npm test       # 테스트 실행
```

## 🔐 계정
- 회원가입/로그인 후 사용, **계정 1개당 프로필 1개**
- 추천·랜덤 매칭은 **로그인한 본인 프로필로만** 가능 (다른 사람 프로필로 참여 불가)
- 비밀번호는 salt + scrypt 해시로 저장, 로그인은 HttpOnly 쿠키
- 전체 프로필 목록·전체 매칭·초기화는 관리자 계정만

| 테스트 계정 | 비밀번호 |
|---|---|
| `test1` ~ `test20` (샘플 프로필 20명) | `test1234` |
| `admin` (관리자) | `admin1234` |

> 두 사람 실시간 테스트는 일반 창과 시크릿 창에서 서로 다른 계정으로 로그인하세요.

## 매칭 로직

### 1단계: 거르기
서로의 조건을 **양방향으로** 확인해서 하나라도 맞지 않으면 제외합니다. 제외된 이유도 함께 보여 줍니다.

| 조건 | 설명 |
|---|---|
| 성별 | 원하는 성별이 아니면 제외 |
| 나이 | 선호 나이 범위 밖이면 제외 |
| 키 | 선호 키 범위 밖이면 제외 |
| 흡연 | "비흡연자만"을 체크했는데 상대가 흡연자면 제외 |
| 종교 | "같은 종교만"을 체크했는데 종교가 다르면 제외 |
| 지역 | "같은 지역만"을 체크했는데 지역이 다르면 제외 |
| 만남 목적 | "가벼운 만남"과 "결혼 전제"처럼 정반대면 제외 |

### 2단계: 점수 매기기 (100점 만점)

| 항목 | 배점 | 기준 |
|---|---|---|
| 관심사 | 25 | 공통 관심사 비율 |
| 만남 목적 | 15 | 같으면 15, 한 단계 차이면 7.5 |
| 나이 | 15 | 나이 차이가 적을수록 높음 (10살 차이면 0) |
| 지역 | 15 | 같은 지역 15, 둘 다 수도권 7.5 |
| 생활습관 | 15 | 음주 스타일(10) + 흡연 여부(5) |
| MBTI | 10 | N/S 같음 +4, E/I 다름 +3, T/F·J/P 다름 각 +1.5 (참고용) |
| 종교 | 5 | 같으면 5 |

### 3단계: 순위 & 매칭
- **추천 보기**: 한 사람 기준으로 거르기를 통과한 상대를 점수 높은 순으로 보여 줍니다.
- **전체 매칭**: 서로 조건이 맞는 모든 쌍을 점수 높은 순으로 정렬해, 아직 짝이 없는 두 사람끼리 1:1로 짝지어 줍니다. 최소 점수(기본 40점) 미만은 매칭하지 않습니다.

### 🎲 랜덤 매칭 + 익명 미션
점수 추천이 맘에 들지 않으면 랜덤 매칭을 할 수 있습니다.
- 대기 중인 사람끼리 무작위로 연결 (원하는 성별만 확인)
- 상대 인적사항은 비공개, `🦊 여우` 같은 익명 닉네임으로만 표시
- 미션은 **둘 다 답해야** 서로의 답이 공개됨
- 매번 서로 다른 종류로 4개를 무작위로 뽑고, 마지막에 "느낀 점 한마디"

| 미션 | 방식 |
|---|---|
| ⚖️ 밸런스 게임 | 둘 중 하나 고르기, 같으면 🎉 통했다 |
| 💭 취향 질문 | 자유롭게 답하기 |
| 🔮 텔레파시 (협동) | 보기 4개 중 같은 걸 고르면 성공 |
| 🎯 숫자 합 맞추기 (협동) | 둘이 고른 숫자의 합이 목표(10 또는 7)와 같으면 성공 |
| 📖 이야기 이어 쓰기 (협동) | 한 명이 첫 문장, 다른 한 명이 이어서 |
| 👍👎 좋아? 싫어? | 서로 주제를 하나씩 내고, 상대 주제를 좋아하는지 답하기 → 취향 일치 확인 |
- 미션 1개마다 💚 계속하기 / ❌ 그만하기 선택 → 한 명이라도 그만하면 관계 종료, 다시 매칭되지 않음
- 마지막 미션까지 끝내면 서로 프로필 공개
- 실시간 연결은 Server-Sent Events 사용 (브라우저 창 두 개로 테스트하거나 🤖 봇과 테스트)

### 🤖 AI 매칭 (로컬 LLM)
로컬에서 돌아가는 LLM(Ollama)이 후보를 **한 명씩 직접 보고** 거를지 · 몇 점인지 · 왜 그런지를 판단합니다.
- 기본 모델: `matching-bot` — EXAONE 3.5 2.4B에 판단 지시문 · 점수 기준 · 예시 판단 3개를 넣은 전용 모델 (없으면 `exaone3.5:2.4b`에 같은 지시문을 매번 보내서 대신함, 환경 변수 `OLLAMA_MODEL`, `OLLAMA_URL`로 변경)
- 작은 모델이 틀리기 쉬운 숫자 비교(나이 범위 등)는 코드가 계산해 **[확인된 사실]**로 함께 전달
- 답은 JSON 형식을 정해서 받음 (통과 여부 / 거른 이유 / 점수 / 태그 / 설명)
- AI가 필수 조건을 놓치고 통과시키면 규칙 검사가 바로잡고 `⚠️ AI가 놓친 조건`으로 표시
- 판단이 끝난 사람부터 실시간으로 화면에 표시 (19명 기준 약 1분)

```bash
ollama pull exaone3.5:2.4b   # 처음 한 번
npm run create:bot           # 전용 모델 matching-bot 만들기 (지시문·예시를 바꾸면 다시 실행)
npm run eval:ai              # AI 판단 품질 평가 (거르기 정확도, 점수 분포, 지어낸 관심사)
npm start                    # Ollama가 켜져 있으면 🤖 AI 매칭 탭 사용 가능
```

#### 💬 AI에게 물어보기
추천 카드의 **💬 AI에게 물어보기** 버튼으로 그 사람에 대해 AI와 대화할 수 있습니다. (예: "취미가 안 겹치는데 왜 어울려?", "첫 데이트로 뭐 하면 좋을까?")
- 두 사람의 프로필 · [확인된 사실] · 항목별 점수 근거 · AI 매칭 판단을 근거로 답함
- "이 사람/그분/상대" 같은 말은 상대 이름으로 바꿔서 전달 (작은 모델의 헷갈림 방지)
- 답은 한 글자씩 실시간으로 표시, 대화 기록은 창을 닫아도 유지
- 대화는 JSON 전용인 matching-bot 대신 기본 모델(`exaone3.5:2.4b`)에 상담 지시문을 붙여 사용

#### 깃허브 페이지에서 AI 쓰기
깃허브 페이지 버전은 브라우저가 **내 컴퓨터의 Ollama**를 직접 부릅니다. Ollama가 깃허브 페이지 주소를 허용하도록 설정한 뒤 Ollama를 다시 켜 주세요. (크롬이 "로컬 네트워크 접근"을 물어보면 허용)

```powershell
setx OLLAMA_ORIGINS "https://jeonghossi.github.io"
```

```
src/matching.js     매칭 로직 (거르기, 점수, 순위, 매칭)

src/auth.js         계정 (비밀번호 해시, 로그인 세션)
src/aiMatch.js      🤖 AI 매칭 (로컬 LLM 판단)
pages/              깃허브 페이지 버전용 브라우저 백엔드
scripts/            docs/ 생성 스크립트
docs/               깃허브 페이지 (자동 생성)

server.js           웹 서버 + API
public/             웹 화면
test/               테스트
```

## API

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/auth/signup` · `login` · `logout` | 회원가입 / 로그인 / 로그아웃 |
| GET | `/api/auth/me` | 내 계정 + 프로필 |
| POST / PUT | `/api/profiles/me` | 내 프로필 만들기 / 수정 |
| GET | `/api/recommendations/me` | 내 추천 순위 + 걸러진 사람 |
| GET | `/api/random/events` | 랜덤 매칭 상태 실시간 수신 (SSE) |
| GET | `/api/ai/status` | 로컬 LLM 연결 상태 |
| GET | `/api/ai-match/stream` | AI 매칭 진행 상황 실시간 수신 (SSE) |
| POST | `/api/ai/ask` | 💬 AI에게 물어보기 (`{ candidateId, messages }` → 답을 NDJSON 스트림으로) |
| POST | `/api/random/join` · `bot` · `cancel` · `answer` · `decide` · `leave` | 랜덤 매칭 동작 |
| GET | `/api/admin/profiles` | (관리자) 전체 프로필 |
| DELETE | `/api/admin/profiles/:id` | (관리자) 프로필 삭제 |
| GET | `/api/admin/matches?minScore=40` | (관리자) 전체 1:1 매칭 |
| POST | `/api/admin/reset` | (관리자) 샘플 데이터로 초기화 |
